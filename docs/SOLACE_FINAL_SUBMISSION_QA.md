## Performance and resources

- `src/practice-insights.ts` filters and sorts only sessions and check-ins. The same synthetic account produced identical results at a median **2.77 ms → 0.97 ms per selector call** on Node 24.22.1. This measures selector work. [Benchmark](../work/overnight-performance/final-measurement.json)
- On the same Android emulator, median cold ActivityManager `TotalTime` was **1.75 s before and 1.27 s after**, and median warm foreground `WaitTime` was **159 ms before and 140 ms after**, from three samples per build. These measure Activity startup and foregrounding. Host load varied, so the samples do not establish a causal startup improvement. ADB and UI hierarchy polling were recorded separately because they add measurement overhead.
- The live Chromium rehearsal recorded first Voice layout at **1.94 s**, readiness at **5.80 s** and decoded first audio at **7.31 s** from the tap. The answer request took about **2.91 s** on the isolated API. This is one development-browser sample with screenshot capture during startup. Reconnection and native voice timing were not measured. [Live demo timing](../work/final-submission-qa/demo-result.json)
- A separate live text request returned an OpenAI response in **3.33 s**. Playback generation returned private, no-store MP3 bytes in **1.86 s**. The API readback preserved both chat messages in order. No audio output route on a physical device was exercised. [Live text and speech](../work/final-submission-qa/live-text-result.json)
- The voice handoff closed its peer and ended microphone tracks before the practice. Chromium verified four concurrent ambient audio clocks, independent mute/unmute, pause, resume, stop and rewind. Android total PSS was approximately **176 MiB** after visiting all five tabs. Device FPS, sustained memory trends and Bluetooth latency remain open.
